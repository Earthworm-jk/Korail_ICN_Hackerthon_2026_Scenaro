## 0. v0.1 대비 확정 변경

- 배우와 작품을 모두 복수 선택할 수 있다.
- 모든 촬영지는 일반 선택 후보이며 `필수 방문` 입력을 두지 않는다.
- 최종 MVP 편집은 `촬영지 제외`와 `입국·출국 항공편 시각 변경` 두 동작이다.
- 방문일 변경·고정과 편집 전후 요약 화면은 최종 MVP에서 제외한다.
- 재계산 성공 시 갱신된 일정만 명확히 표시하고, 실패 시 기존 일정을 유지한다.
- 저장 시점의 점진적 인증과 계정별 일정 저장·재열람을 포함한다.
- Supabase Auth + PostgreSQL + RLS를 인증·저장 계층으로 사용한다.
- Rail&Air 조건·발권 채널 안내는 참가신청서와 발표자료의 약속이 아니므로 MVP에서 제외한다.
- 운영시간은 추천 배치와 경고에 사용한다. 운영시간 밖이라는 이유만으로 장소를 숨기지 않으며,
  철거 또는 접근 불가가 확인된 장소만 추천 데이터에서 제외한다.

## 1. 제품 정의

**씬나로(SCENARO)**는 방한 외국인 여행자가 좋아하는 배우와 드라마·영화를 선택하면,
검증된 촬영지를 항공편 시간 경계와 실제 철도 시간표 안에서 방문할 수 있도록 일정을 만들고,
조건이 바뀌면 전체 일정을 다시 계산하는 웹서비스다.

씬나로는 예약·결제 서비스가 아니라 여행 의사결정 서비스다. 규칙 기반 플래너가 항공 경계와
철도 시간표를 계산하며, LLM은 사실 판정이나 시간 계산에 사용하지 않는다.

## 2. 목표 사용자와 문제

### 핵심 사용자

- K-드라마·영화·배우에 관심이 있는 방한 외국인 개별 여행자
- 인천공항으로 입출국하고 철도로 지역 촬영지를 방문하려는 여행자
- 패키지보다 자신의 콘텐츠 취향과 항공 일정에 맞춰 여행을 조율하려는 사용자

### 해결하려는 문제

- 배우·작품·촬영지 관계가 여러 사이트에 흩어져 있다.
- 항공편과 열차 시간표 안에서 실제 방문 가능한지 직접 계산하기 어렵다.
- 운영시간과 역–장소 접근 추정치를 함께 판단하기 어렵다.
- 장소 제외나 항공편 변경 후 전체 일정을 다시 만들어야 한다.
- 저장한 계획을 여행 직전이나 여행 중 다시 열어 대응하기 어렵다.

## 3. 제품 원칙

1. **검증된 관계만 표시한다.** 배우–작품–촬영지 관계에는 출처와 확인일을 남긴다.
2. **계산과 설명을 분리한다.** 규칙 기반 엔진이 계산하고 LLM은 계산에 참여하지 않는다.
3. **모르는 것을 만들지 않는다.** 실시간 조회 실패 시 출처가 있는 스냅샷으로 폴백한다.
4. **추정치를 정직하게 표시한다.** 역–장소 접근시간은 대표 추정치이며 실제 경로가 아니다.
5. **사용자의 방문 의도를 단정하지 않는다.** 운영시간은 배치 선호·경고 정보로 사용한다.
6. **불가능한 일정을 억지로 만들지 않는다.** 실패 이유와 바꿔볼 조건을 제공한다.

## 4. 최종 MVP 사용자 흐름

```text
항공편·여행 조건 입력
  → 배우·작품 복수 검색 및 선택
  → 연결된 촬영지 후보 확인·선택
  → 일정 생성
  → 추천 일정·검증 대안 확인
  → 촬영지 제외 또는 항공편 시각 변경
  → 전체 재계산·갱신된 일정 확인
  → 이 코스 저장하기
  → 비로그인 사용자만 이메일+비밀번호 인증
  → 자동 저장 → 내 일정 → 다시 열기·재계산
```

로그인은 탐색과 일정 생성의 선행 조건이 아니다. 인증 취소·실패 시에도 현재 코스와 선택 상태를
유지한다.

## 5. 기능 범위

### 5.1 여행 조건과 항공편

- 입국편·출국편 번호 또는 날짜·시각 입력
- 항공 데이터 조회 성공 시 예정·변경 시각 자동 반영
- 조회 실패 시 수동 입력과 스냅샷 폴백 제공
- 항공편 도착 후 공항 출발 가능 시각 확인·수정
- 귀국 시 공항 도착 마감 시각 확인·수정
- 여유는 선택한 절대 시각에서 파생 표시하며, 기본 제안은 입국편 도착 +120분·출국편 출발 -120분
- 공항에서 철도 관문 또는 지역으로 이동하는 수단 안내
- 지역 내 실제 버스·택시·도보 경로와 요금은 계산하지 않음

### 5.2 배우·작품 탐색

- 배우·작품 통합 검색과 자동완성
- 배우와 작품 모두 복수 선택 가능
- 배우만, 작품만, 배우+작품 조합 모두 허용
- 선택 배우와 무관한 작품도 함께 선택 가능
- 후보 촬영지는 `선택 배우 관련 장소 ∪ 선택 작품 관련 장소`로 만들고 ID 기준 중복 제거
- 한국어·영어 검색 및 표시 이름 지원

### 5.3 촬영지 후보와 선택

- 모든 장소는 일반 `선택`이며 별도의 `필수 방문` 상태를 두지 않음
- 사용자가 선택한 장소를 엔진이 최대한 배치
- 카드에 작품 관계, 연결역, 대표 접근시간, 운영시간, 출처, 검증일 표시
- 운영시간 미확인 또는 시간대 불일치는 경고로 표시하고 후보 자체를 숨기지 않음
- 철거 또는 접근 불가가 공식적으로 확인된 장소만 추천 데이터에서 제외
- 선택 장소가 많으면 모두 방문하지 못할 수 있다는 안내 표시

후보 기본 정렬은 관련성순이며 공식 출처순으로 전환할 수 있다.

1. 관련성순: `selected_work → actor_other_work → officialSourceCount 내림차순 → placeId 오름차순`
2. 공식 출처순: `officialSourceCount 내림차순 → 관계 유형 → placeId 오름차순`

### 5.4 일정 생성 엔진

다음 하드 제약을 통과한 일정만 비교한다.

- 연결 가능한 공항 이동·열차 시간표 존재
- 사용자가 제외한 장소 미포함
- 출국 안전 여유를 포함한 공항 도착 마감 준수

운영시간과 대표 접근시간은 #43에 따라 보수적인 일정 배치 및 사용자 경고에 사용한다. 운영시간 밖 방문은
내부 관람이 어려울 수 있음을 알리되, 장소가 존재하고 외부 접근이 가능하면 후보에서 자동
삭제하지 않는다.

통과한 일정은 다음 순서로 결정적으로 비교한다.

1. 선택 배우·작품 관련성
2. 방문 가능한 촬영지 수
3. 운영시간 경고 수(적을수록 우선)
4. 총 철도 이동시간
5. 환승 횟수
6. 방문일별 일반 여유 충족 여부

동일 입력은 항상 동일 결과를 반환하며 시드 규모에서 생성·재계산 목표는 2초 이내다.

### 5.5 추천 일정과 검증 대안

- 추천 일정 1개를 기본 표시
- 모든 하드 제약을 통과한 검증 대안 최대 2개 제공
- 각 DAY의 열차 항목에서 다른 출발 시각을 선택할 수 있도록 표현
- 대안 선택 시 개별 열차만 부분 교체하지 않고 전체 일정을 다시 검증·교체
- 대안에서도 현지 활용 가능 시간, 장소 변화, 이동·환승, 출국 여유 표시
- 사용자 화면에는 열차 출발·도착 시각과 역 기준 현지 활용 가능 시간을 표시
- 지역 내 이동을 계산한 것처럼 장소별 확정 도착·출발 시각을 표시하지 않음

### 5.6 편집과 전체 재계산

최종 MVP 편집 동작은 두 가지다.

1. 촬영지 제외
2. 입국·출국 항공편 시각 변경

두 동작 모두 변경된 일부 구간을 임의로 패치하지 않고 전체 일정을 처음부터 다시 계산한다.

- 성공: 갱신된 일정을 명확히 표시
- 변화 없음: `조건은 반영됐지만 일정 구성은 동일합니다` 표시
- 실패: 기존 일정 유지, 사유와 바꿔볼 조건 표시
- 처리 중 중복 입력 차단

방문일 변경·고정 UI와 이전/새 일정의 별도 전후 요약 화면은 MVP에서 제공하지 않는다.

### 5.7 실행 지원

- 공항에서 철도 관문 또는 지역으로 이동하는 수단과 환승 단계 안내
- 지역역 편의시설과 정적 짐 보관 정보
- 지도는 실제 내비게이션이 아니라 일정의 지역 관계를 보여주는 보조 시각화로 사용
- Rail&Air 조건·공식 발권 채널 전용 화면은 제공하지 않음

## 6. 저장과 점진적 인증

### 6.1 사용자 경험

- 비로그인 상태에서도 탐색·생성·대안·편집·재계산까지 이용 가능
- `이 코스 저장하기` 시점에만 인증 요청
- Guest 로컬 저장은 MVP에서 제외
- 기본 인증은 관리형 이메일+비밀번호
- 인증 성공 시 보던 코스를 자동 저장하고 같은 결과 화면으로 복귀
- 인증 취소·실패 시 코스와 선택 상태 유지
- 내 일정 목록·상세·다시 열기·재계산 제공

### 6.2 기술 경계

- 인증·사용자·세션: Supabase Auth
- 저장 일정: Supabase PostgreSQL
- 사용자별 권한: RLS, `auth.uid() = user_id`
- 플래너 시드·시간표·항공 스냅샷: 서버 전용 JSON Repository
- 플래너 엔진은 사용자·세션·Supabase를 모르게 유지
- 자체 비밀번호 저장·해싱 금지
- service role key 클라이언트 노출 금지

### 6.3 저장 일정 최소 데이터

```text
saved_itineraries
├─ id
├─ user_id
├─ title
├─ constraints JSON
├─ constraints_hash
├─ itinerary JSON
├─ schema_version
├─ snapshot_version
├─ created_at
└─ updated_at
```

기본 제목은 권역·기간·대표 콘텐츠를 조합해 생성한다. 같은 constraints 해시가 있으면 새로 저장
또는 덮어쓰기를 선택하게 한다. 저장 당시와 현재 스냅샷이 다르면 다시 계산하기를 안내한다.

## 7. 실패와 복구

### 일정 상태

- `planned`: 선택된 일정 존재
- `empty`: 정상 계산됐지만 조건을 만족하는 일정 없음

### 후보 제외·경고 사유

- `TRAIN_UNAVAILABLE`: 연결 가능한 열차가 없음
- `DEPARTURE_DEADLINE_EXCEEDED`: 출국 역산 마감 초과
- `ACTIVITY_WINDOW_MISMATCH`: 운영시간 또는 보수적 접근시간 기준 경고

재계산 결과가 `empty`이면 기존 일정을 유지하고 바꿔볼 조건을 표시한다. 방문일 고정과 필수 방문이
없으므로 `PINNED_DATE`, `REQUIRED_PLACE`, `USER_CONSTRAINT_INFEASIBLE` 계약은 사용하지 않는다.

## 8. 언어

핵심 사용자 흐름 전체를 한국어와 영어로 제공한다.

- 여행 조건·항공편
- 배우·작품 검색
- 촬영지 후보·선택
- 추천 일정·검증 대안
- 편집·재계산·실패 복구
- 로그인·저장·내 일정·재열람

모든 사용자 문구는 ko/en 번역 객체로 분리하고 시드에는 영문 필드를 둔다.

## 9. 콘텐츠·데모 범위

### 최종 MVP 데이터 목표

- 드라마·영화 8~12편
- 대표 배우 4~6명
- 검증 촬영지 30~50곳
- KTX 권역 2~3개
- 장소·작품·배우명 ko/en
- 출처 URL·검증일·운영시간·연결역·대표 접근시간

### 라이브 데모 필수 장면

- 배우·작품 선택과 촬영지 후보
- 추천 일정과 검증 대안
- 촬영지 제외 후 전체 재계산
- 항공편 2시간 지연 후 전체 재계산
- 갱신된 일정 또는 구체적인 불가능 사유
- 저장 → 내 일정 → 다시 열기 → 재계산

방문일 변경과 편집 전후 요약은 데모 장면에 포함하지 않는다.

## 10. 오프라인·온라인 데모 계약

- `탐색 → 생성 → 대안 → 편집·재계산`은 네트워크 없이 스냅샷으로 완주
- `인증 → 저장 → 내 일정 → 재열람`은 Supabase 네트워크 전제
- 데모는 사전에 생성한 계정과 유지된 세션을 기본으로 사용
- 네트워크 장애 시 저장 장면은 사전 녹화 백업으로 전환

## 11. 성공 기준

### 제품·정확도

- 검증되지 않은 배우–작품–촬영지 관계 표시 0건
- 열차 시간표·출국 역산 하드 제약 위반 0건
- 운영시간·접근 추정치·출처·검증일 표시
