# 멘토링 AI 시연 런북

관련: #78, 신청서 「AI가 맡는 일」, PR #79, #80

유지 정책: 멘토링 종료 후 회고에서 이 런북의 재사용·갱신·삭제 여부를 결정한다.

## 목표

멘토가 화면만 보고도 다음 세 책임을 구분하게 한다.

1. **LLM**: 외국어 표기·별칭·오탈자를 제한된 배우·작품 ID로 해석한다.
2. **검토된 AI 랭킹**: 검증된 촬영지 후보의 관련성 순서와 설명만 보조한다.
3. **결정적 일정 엔진**: 항공·철도·운영시간·여유 시간으로 실행 가능성을 계산한다.

정확도가 중요한 사실관계와 일정 계산을 LLM이 수행한다고 설명하지 않는다.

## 세션 전 프리플라이트

- 최신 `dev` 기준 화면인지 확인한다.
- 로컬 `.env.local`의 `OPENAI_API_KEY` 설정 여부만 확인하고 키 값은 화면·로그에 노출하지 않는다.
- `Kim Goeun`, `도께비`, `도깨비`를 한 번씩 실행해 결과를 확인한다.
- 내부 안전성 점검으로만 `영진해변`을 입력해 결과가 없는지 확인하고, 메인 시연에서는 보여주지 않는다.
- 한국어와 영어 UI에서 AI 해석 안내와 검토된 관련 이유가 모두 읽히는지 확인한다.
- OpenAI 장애·키 누락 시 기존 ko/en 검색과 전체 일정 생성이 유지되는지 확인한다.
- #80 테마체험 카드는 dev 병합 전까지 구현 완료로 설명하지 않는다.

## 화면만 보여주는 첫 5분

최경식 멘토 세션에서는 먼저 기능을 해설하지 않는다. 아래 순서로 조작하고, 멘토가 이해한 내용을 기록한다.

1. 여행 조건 화면에서 기본값으로 `다음`을 누른다.
2. `Kim Goeun`을 입력한다.
   - 기대 화면: **김고은 배우 1건**과 `AI가 입력 표현을 해석...` 안내.
   - 관찰: 멘토가 AI 해석과 결과 선택의 관계를 이해하는가?
3. 김고은을 선택하고 촬영지 단계로 이동한다.
   - 기대 화면: 해당 장면의 김고은 등장이 검토로 확정된 장소만 표시. 미등장·미검토 장소는 노출하지 않는다.
4. 관련성순에서 `✨ 검토된 관련 이유`를 확인한 뒤 공식 출처순으로 전환한다.
   - 관찰: AI 관련성, 공식 근거, 사용자 선택이 구분되는가?
5. 장소를 선택해 추천 일정 1개를 생성한다.
   - 관찰: AI가 일정을 생성한다고 오해하는가, 엔진 계산으로 이해하는가?

첫 5분 뒤 다음 한 문장만 질문한다.

> 화면만 보셨을 때 AI가 한 일과, 시간표를 계산한 부분이 각각 무엇으로 보였나요?

## 설명 가능한 3분 AI 시연

첫인상 관찰이 끝난 뒤에만 아래 세 입력을 비교한다.

| 입력 | 기대 결과 | 보여주는 경계 |
|---|---|---|
| `김고은` | 김고은, AI 안내 없음 | 기존 결정적 검색 우선 |
| `Kim Goeun` | 김고은, AI 해석 안내 | 외국어 표기 변형 해석 |
| `도께비` | 도깨비, AI 해석 안내 | 대표 오탈자 해석 |

이후 `도깨비`를 직접 선택해 촬영지 화면에서 다음을 보여준다.

- `관련성순`: 오프라인 임베딩 결과 중 사람이 검토한 순위만 적용.
- `공식 출처순`: AI 점수와 무관한 독립 기준.
- `검증된 관련 이유`: 공식 관계·장면 근거를 사용하고 원시 점수는 숨김.
- 일정 결과: AI가 아니라 제약조건 엔진이 항공·철도·운영시간을 계산.

`영진해변`은 자동 검증의 설명 사례다. 원천 CSV의 `도깨비 방파제` 문장만으로는 김고은
등장을 추론하지 않았지만, 한국관광공사 공식 자료가 `은탁(김고은)` 장면을 명시해 A등급으로
승격했다. 따라서 `김고은` 배우 선택과 `도깨비` 작품 선택 모두 촬영지 단계에서 영진해변을
보여준다. 장소명 자체를 배우·작품 검색 결과로 오해해 반환하지 않는 경계는 유지한다.

## 1분 기술 설명

> 씬나로는 AI가 사실을 지어내거나 일정 시간을 계산하게 하지 않습니다. 런타임 LLM은 사용자의
> 표현을 제공된 배우·작품 ID 안에서만 해석합니다. 데이터 수집 단계의 AI는 출처와 근거 문장을
> 구조화합니다. 장소·작품 일치와 배우 명시는 모델 추출 판단이지만, 그 입력을 함께 저장하고
> 공식 출처 1개 또는 독립 편집 출처 2개라는 고정 결합 규칙으로 자동 승격 범위를 제한합니다.
> 미확정·충돌은 노출하지 않고 표본·예외만 사람이 감사합니다. 마지막 일정은 항공·KTX·운영시간을
> 제약조건 엔진이 계산하므로 AI가 실패해도 검증된 검색과 일정 생성은 유지됩니다.

## 정직하게 답할 제한 사항

- 현재 검증 범위와 신청서 목표 범위를 구분해 말한다.
- 좌석 가용성·예약 가능성·입국 완료 시각은 보장하지 않는다.
- AI는 촬영지 사실관계를 생성하지 않고 출처에서 추출한다. 운영시간·이동시간은 생성하지 않는다.
- 테마체험 연결은 #80이 병합되기 전에는 진행 중으로 말한다.
- 서버 메모리 캐시는 인스턴스 재시작 시 사라지며 비용 방어용 보조 장치다.

## 실패 시 복구 순서

1. LLM 응답이 없으면 `김고은` 또는 `도깨비` 직접 검색으로 흐름을 계속한다.
2. `OPENAI_API_KEY` 값을 화면에 열지 말고 설정 여부만 확인한다.
3. AI 실패가 일정 엔진 실패가 아님을 설명하고, 폴백이 유지되는 화면을 보여준다.
4. 멘토에게 성공 화면을 가장해 설명하지 않는다. 재현 조건과 후속 확인 항목으로 기록한다.
