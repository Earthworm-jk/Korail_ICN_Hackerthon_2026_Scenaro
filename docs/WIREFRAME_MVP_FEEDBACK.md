- 결정 기준: GitHub 이슈 #14, `docs/WIREFRAME_GUIDE.md`

## 1. 검토 결론

현재 시안의 화면 구성과 시각 방향은 유지한다. 발표자료의 밝고 정돈된 인상, 코레일 블루 중심의 색상, 좌측 선택 요약, 촬영지 목록과 지도, 일정과 지도의 결합이 제품의 핵심 흐름을 잘 보여준다.

현재 4개 화면은 **정상 흐름의 핵심 시안으로 승인**한다. 다만 최종 MVP에는 인증·계정·저장과 각종 로딩·실패·복구 상태까지 포함되므로, 아래 차단 수정과 추가 프레임을 반영한 뒤 최종 확정한다.

이 문서에서 말하는 MVP는 시연용 한 장짜리 P0 화면이 아니라 사용자가 로그인하고 일정을 생성·조정·저장·재열람할 수 있는 최종 MVP다. P0/P1 표시는 개발 순서일 뿐 와이어프레임 제외 기준이 아니다.

## 2. 그대로 유지할 부분

- 4단계 핵심 흐름을 한눈에 이해할 수 있는 정보 구조
- 발표자료를 계승한 흰 배경, 코레일 블루, 얇은 구분선과 카드
- 좌측 내비게이션과 선택 요약
- 작품 카드와 배우 목록의 시각적 구분
- 촬영지 목록과 지도 동시 배치
- DAY별 일정과 전체 지역 지도를 함께 보는 결과 구조
- 결과 하단의 `다른 시간표 보기` 진입점
- 항공·철도·장소를 색과 아이콘으로 구분하는 방식

## 3. 전체 화면 공통 수정

### 3.1 단계와 내비게이션

- 로그인 전에는 인증 화면, 로그인 후에는 일정 생성 흐름을 제공한다.
- 좌측 메뉴의 `로그인`은 로그인 후 `내 계정` 또는 사용자 메뉴로 전환한다.
- 현재 위치, 완료 단계, 수정 가능한 단계를 색상뿐 아니라 아이콘과 텍스트로 구분한다.
- `일정 저장`과 `공유`를 하나의 버튼으로 합치지 않는다. 저장을 기본 동작으로 두고 공유는 별도 버튼 또는 메뉴로 분리한다.

### 3.2 지도 표현

- 지도는 지역 간 관계와 일정 순서를 보여주는 보조 시각화다.
- 실제 버스·택시·도보 경로를 계산한 것처럼 보이는 범례와 문구를 사용하지 않는다.
- `역–장소 접근시간은 이동수단을 포함하지 않은 대표 추정치입니다` 안내를 제공한다.
- 동적 지도 구현 전에는 정적 지도 또는 단순 경로 개념도로 대체할 수 있게 설계한다.

### 3.3 접근성과 상태

- 선택·완료·경고를 색상만으로 구분하지 않는다.
- 클릭 영역은 최소 높이 44px을 확보한다.
- 처리 중에는 관련 버튼과 입력을 잠그고 중복 요청을 막는다.
- 모든 아이콘 버튼에 텍스트 라벨 또는 툴팁을 제공한다.

## 4. 화면 1 — 여행 조건 입력

### 유지

- 입국편과 출국편을 나란히 비교하는 카드
- 이동 가능 시간의 요약
- 다음 단계 버튼과 좌측 선택 요약

### 수정

1. `KTX 우선 / 시간 최소 / 환승 최소` 교통 우선순위 영역을 제거한다. 엔진의 점수 서열은 사용자가 바꾸지 않는다.
2. 출국 안전 여유를 선택할 수 있게 한다.
   - 기본값: 120분
   - 프리셋: 90분 / 120분 / 180분
   - 직접 입력은 개발 범위가 확정될 때 추가
3. 여행 기간은 입출국 날짜에서 자동 계산되는 값임을 명확히 한다. 기간 버튼이 항공 날짜와 충돌하는 별도 입력처럼 보이지 않게 한다.
4. 이동 가능 시간에는 산식의 기준을 짧게 표시한다.
   - 예: `입국 12:00 이후 · 출국일 16:30까지 (출국 여유 180분)`

## 5. 화면 2 — K-콘텐츠 검색

### 유지

- 배우·작품 통합 검색
- 작품 카드와 배우 행
- 선택한 콘텐츠를 하단 칩으로 요약하는 방식

### 수정

1. 검색 결과마다 `배우` 또는 `작품` 유형을 표시한다.
2. 배우는 최대 1명, 작품은 복수 선택 가능하다는 규칙을 선택 영역 근처에 안내한다.
3. 배우 없이 작품만, 작품 없이 배우만 선택할 수 있다.
4. 선택 배우와 무관한 작품도 함께 선택할 수 있어야 한다.
5. 배우를 선택하면 관련 작품을 추천 영역에 노출하되 다른 작품 검색·선택을 막지 않는다.
6. 검색 결과 없음 상태에는 입력어, 사유, 추천 배우·작품, 검색 초기화 동작을 제공한다.

## 6. 화면 3 — 촬영지 후보 확인과 필수 방문

### 유지

- 좌측 장소 목록과 우측 지도
- 관련 작품과 지역 정보가 함께 보이는 카드
- 지도 핀과 카드 선택의 연동

### 차단 수정

1. `필수 방문 장소 최대 6곳` 제한을 제거한다.
2. 일반 후보 선택과 필수 방문 지정을 구분한다.
   - 기본 상태: 필수 아님
   - 명시적 동작: `필수 방문으로 지정`
   - 필수 상태: 별 아이콘·배지·텍스트로 표시
3. 필수 장소를 많이 지정하면 일정 생성이 어려워질 수 있다는 안내를 제공한다.

### 장소 카드 필수 정보

- 장소명과 썸네일
- 관련 작품
- 연결역
- 역–장소 추정 접근시간
- 운영시간 또는 상시 개방
- 출처와 검증일
- `추정치`, `운영시간 확인 필요`, `공식 정보` 등의 상태 배지
- 필수 방문 지정·해제 동작

## 7. 화면 4 — 일정 생성 결과와 수정

### 유지

- DAY별 일정 목록과 전체 지도
- 항공·철도·장소의 시각적 구분
- 접힌 `다른 시간표 보기`

### 차단 수정

1. 연필 아이콘만 두지 말고 다음 편집 동작을 명시한다.
   - 촬영지 제외
   - 방문일 변경
   - 항공편 시각 변경
2. 각 DAY 또는 장소 상세에 다음 정보를 제공한다.
   - 열차 출발·도착역과 시각
   - 촬영지와 관련 작품
   - 역–장소 추정 접근시간
   - 운영시간 또는 상시 개방
   - 정보 출처·검증일·추정치
3. 편집 확인 후 전체 일정을 재계산하며 처리 중에는 다른 편집을 잠근다.
4. 재계산 성공 시 결과 상단에 바뀐 항목만 표시한다.
5. 재계산 실패 시 기존 일정을 그대로 유지하고 사유와 수정 가능한 조건을 보여준다.

### 다른 가능한 시간표

접힌 영역을 펼치면 추천 외 검증 대안 최대 2개를 표시한다. 각 대안에는 다음 비교값이 필요하다.

- 출발·귀환 시각
- 현지 활용 가능 시간
- 촬영지 변화
- 이동시간·환승 변화
- 출국 여유

대안을 선택하면 열차 한 편이 아니라 검증된 전체 일정으로 교체한다.

### 저장과 공유

- Primary: `일정 저장`
- Secondary: `공유 링크 복사` 또는 `내보내기`
- 저장 중, 저장 성공, 저장 실패, 로그인 필요 상태를 각각 설계한다.
- 저장 성공 후 `내 일정 보기` 동작을 제공한다.

- 저장되지 않은 변경이 있을 때 이탈 경고

## 9. 추가로 제작할 상태 프레임

기존 정상 화면 외에 다음 상태가 필요하다.

| 상태 | 핵심 화면 계약 |
|---|---|
| 검색 결과 없음 | 사유, 추천 콘텐츠, 검색 초기화 |
| 생성 전 최종 확인 | 항공편·여유·콘텐츠·필수 장소·추정 정책 요약 |
| 일정 생성 중 | 입력 잠금, DAY 스켈레톤, 진행 안내 |
| 최초 생성 불가 | 기존 일정 없음, 원인과 조건 수정 동선 |
| 재계산 성공 | 변경된 항목만 상단 요약 |
| 재계산 실패 | 기존 일정 유지, 실패 사유와 복구 동선 |
| 저장 중·성공·실패 | 버튼 잠금, 토스트 또는 인라인 상태, 재시도 |
| 인증 만료 | 현재 입력 보존, 재로그인 후 작업 복귀 |
| 스냅샷·오프라인 | 데이터 기준일과 제한 사항 안내 |

## 10. 촬영지 사진 정책

### 결론

**사용 조건이 확인된 실제 사진을 우선하고, 없으면 통일된 플레이스홀더를 사용한다. 특정 실제 장소를 AI 이미지로 대체하지 않는다.**

### 사진 확보 우선순위

1. 한국관광공사 TourAPI 이미지
2. 공공누리 제0·제1유형 이미지
3. 지자체·관광기관이 재사용을 명시적으로 허용한 이미지
4. 팀 직접 촬영 또는 권리자의 사용 허락을 받은 이미지
5. SCENARO 공통 플레이스홀더

한국관광공사 관광정보 API는 자유롭게 활용 가능한 관광정보와 사진을 선별해 제공하지만, 사진을 기업 CI·BI로 이용하는 것은 금지한다.

- 한국관광공사 TourAPI: https://www.data.go.kr/data/15101578/openapi.do
- 공공누리 이용조건: https://www.kogl.or.kr/info/userQnaList.do

### 금지·주의

- 방송 화면 캡처, 포털 이미지 검색 결과, 블로그 사진을 허락 없이 사용하지 않는다.
- AI 이미지를 실제 장소 사진처럼 표시하지 않는다.
- 공공누리 제2~4유형은 상업 이용·변경 제한을 개별 확인하기 전 사용하지 않는다.
- 작품 포스터·스틸컷은 촬영지 사진과 별도 저작권이므로 별도 사용 근거가 없으면 제목 중심 카드나 플레이스홀더를 사용한다.

### 데이터 필드

```text
imageUrl
sourceName
sourceUrl
licenseType
licenseUrl
attribution
verifiedAt
fallbackType
```

- 카드에는 사진을 간결하게 표시하고 상세 화면에서 출처를 확인할 수 있게 한다.
- 데모 안정성을 위해 허용된 이미지는 출처·라이선스와 함께 정적 자산으로 캐시한다.
- 사진이 없는 장소도 카드 높이와 비율이 달라지지 않도록 플레이스홀더를 동일 규격으로 제작한다.

## 12. 최종 검수 체크리스트

- [ ] 교통 우선순위 선택이 제거되었는가
- [ ] 출국 여유를 선택할 수 있고 기본값 120분이 보이는가
- [ ] 배우와 무관한 작품도 함께 선택할 수 있는가
- [ ] 후보 선택과 필수 방문 지정이 구분되는가
- [ ] 필수 방문 개수에 임의 제한이 없는가
- [ ] 지도와 접근시간이 실제 지역 교통 계산처럼 보이지 않는가
- [ ] 결과에 운영시간·출처·검증일·추정치가 포함되는가
- [ ] 편집 3동작과 전체 재계산이 명확한가
- [ ] 추천 1개와 접힌 검증 대안 2개가 표현되는가
- [ ] 최초 생성 실패와 재계산 실패가 구분되는가
- [ ] 로그인·회원가입·계정·저장·재열람 흐름이 있는가
- [ ] 저장과 공유가 별도 동작으로 구분되는가
- [ ] 사진의 출처·라이선스·대체 상태가 설계되어 있는가
- [ ] 주요 모바일 화면과 키보드 접근이 고려되었는가
