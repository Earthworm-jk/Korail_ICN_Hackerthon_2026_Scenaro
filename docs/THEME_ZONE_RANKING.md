# 테마체험 권역 관련성 랭킹 입력 규칙 v1

관련: #80, #38, #14 v0.6, #48

## 범위

- 추천 단위는 특정 업체가 아니라 **권역**이다. 개별 업체·가격·운영시간을 추천하거나 보증하지 않는다.
- 카드는 주변 제안이며 현재 일정에 자동으로 포함되지 않는다.
- 테마 권역 랭킹용 OpenAI API는 Python 오프라인 파이프라인에서만 호출한다. 런타임은 검토된 스냅샷만 결정적으로 읽는다 — `API_SPEC.md`의 런타임 예외 목록은 변경되지 않는다.
- 화면 상태는 3분기다: 표시 / 추천 없음(관련도 기준 미통과) / 추천 불가(검증 스냅샷 누락).

## 근거 2종 — 하나라도 없으면 수록하지 않는다

| 근거 | 어디에 | 무엇을 증명하나 |
|---|---|---|
| 권역 공식 관광정보 출처 | `theme-zones.json`의 `sourceUrls` | 권역의 실재·성격 (예: 덕수궁이 대한제국의 황궁) |
| 작품 서사 연결 근거 | `theme-zone-rankings.json` 항목의 `sourceUrls` | 작품의 장르·시대 배경 (예: 《더 킹》의 대한제국 설정) |

권역 공식 출처만으로는 "이 작품과 연결된다"가 증명되지 않으므로 두 근거를 분리해 요구한다. 근거가 확보되지 않은 조합은 미검토로 남기고 화면에 내보내지 않는다.

## 임베딩 입력

- 작품: `data/place-ranking-inputs.json`의 작품 설명문을 **재사용**한다. 같은 작품을 두 곳에 다르게 적으면 설명이 어긋난다.
- 권역: `권역명 — 공간 성격 1문장 + 공식 출처로 확인된 역사·문화 맥락 1문장` (`data/theme-zone-ranking-inputs.json`)
- **권역 문장에 작품명을 넣지 않는다.** 넣으면 "이 권역은 그 작품과 관련 있다"는 결론을 입력에 심고 그 유사도를 근거로 되파는 순환이 된다.
- 입력은 한국어 한 벌로 고정한다. 규칙이 바뀌면 `inputRuleVersion`을 올리고 전체 조합을 다시 평가한다.
- 영어는 사용자에게 표시할 `reason.en`에만 사용한다.

## 임계값 — v1 임시 사전 등록값

- `badgeThreshold`의 v1 값은 **임시 사전 등록값**이며, 촬영지 랭킹(`PLACE_RANKING.md`)의 값을 참고해 API 호출 **전에** 등록한다.
- 촬영지 랭킹의 임계값이 테마 권역에도 그대로 유효하다고 단정하지 않는다. 촬영지 설명문은 작품명을 포함하지만 권역 설명문은 포함하지 않으므로 점수 분포가 다르다.
- **통과 0건이어도 임계값을 바로 낮추지 않는다.** 카드가 뜨도록 입력 문장을 임의로 고치지도 않는다.
- 입력 규칙을 고치는 경우에만 `inputRuleVersion`을 올리고 전체 조합을 재평가하며, 그 경위를 #80에 기록한다.

### 양성·음성 기대 조합 (사전 등록)

호출 전에 등록한 기대 조합이며, 실측 결과와 함께 #80에 기록한다. 회귀 테스트(`lib/__tests__/theme-experience.test.ts`)가 임계값과 무관하게 **순서**를 고정한다.

- 양성: `work-the-king` × `zone-seoul-jeongdong-daehan` (대한제국 배경 작품 × 대한제국 황궁 권역)
- 음성: `work-yumi-cells` × `zone-seoul-jeongdong-daehan`, `work-little-women` × 두 권역 (시대 연결 없는 현대물)

### 실질 게이트는 사람 검토다

데이터가 작을 때 임계값 하나로 표시 여부를 가르는 것은 안정적이지 않다. 이 트랙에서 화면 표시의 실질적인 게이트는 **사람 검토**다 — `reviewed: true`와 근거 2종이 모두 있는 항목만 카드에 나간다. 점수만으로는 어떤 항목도 표시되지 않는다.

## 스냅샷 계약

```json
{
  "meta": {
    "model": "text-embedding-3-small",
    "inputRuleVersion": "v1",
    "generatedAt": "2026-08-09T18:31:43+09:00",
    "badgeThreshold": 0.25
  },
  "rankings": [
    {
      "workId": "work-the-king",
      "zoneId": "zone-seoul-jeongdong-daehan",
      "score": 0.2384,
      "reviewed": false
    }
  ]
}
```

- 생성 직후에는 전건 `reviewed: false`다. 사람이 근거 2종을 확인한 항목만 `reviewed: true`·`reviewedAt`·`reviewedBy`·`sourceUrls`·`reason`을 얻는다.
- 하한을 넘은 검토 항목에 `reason` 또는 `sourceUrls`가 없으면 **로드에 실패한다** — 근거 없는 문장이 화면에 나가는 것보다 실패가 낫다.
- 원시 점수·검토 메타는 클라이언트로 내리지 않는다. 서버 액션은 표시에 필요한 값만 반환한다.

## 런타임 선택 규칙

1. 표시 중인 일정의 `regionId` ∩ 선택 작품으로 후보를 제한한다.
2. 검토 완료 + 하한 통과 항목만 남긴다.
3. 점수 내림차순 → `zoneId` → `workId` 순으로 1건을 고른다 (#3 결정적 타이브레이커).
4. 후보가 없으면 "추천 없음", 카탈로그·스냅샷 자체가 없으면 "추천 불가"를 표시한다.

## 실행

```bash
python3 -m scripts.build_theme_zone_rankings --dry-run
```

`OPENAI_API_KEY`가 있는 오프라인 환경에서만 실행한다. `--dry-run`은 점수만 출력하고 파일을 쓰지 않는다.
