# 배우–장면 근거 자동 검증 계약 v1

관련: #3, #51, PR #92

## 목표와 경계

실서비스에서 모든 작품–장소–배우 관계를 사람이 전수 검토하지 않는다. OpenAI는 웹 검색과
구조화 추출로 **근거 후보**를 만들고, 확정 여부는 결정적 코드가 판정한다. 사용자가 배우를
검색할 때마다 웹을 다시 조회하지 않으며, 승인된 결과를 Supabase/시드에 저장해 재사용한다.

LLM의 작품 출연 지식이나 `작품 촬영지 → 주연 배우 등장` 추론은 근거가 아니다. 원문에 배우명
또는 검증된 `배역(배우)` 연결이 있고 장소·작품이 모두 일치해야 한다.

## 파이프라인

1. 신규·누락 관계를 비동기 수집 큐에 넣는다.
2. OpenAI Responses API의 Web Search로 공식·편집 출처를 찾는다.
3. Structured Outputs로 URL, 출처 등급, 장소·작품 일치, 등장/미등장 주장,
   배우 직접 명시, 배역–배우 연결을 `ActorPresenceEvidence`로 추출한다.
4. `decideActorPresence()`가 아래 규칙으로 판정한다.
5. A/B만 `actorPresenceReviewed:true`와 `featuredActorIds`에 승격한다. 미확정·충돌은 배우 후보에
   노출하지 않고 재수집·예외 감사 대상으로 보낸다.
6. URL·검증일·방법·등급을 관계에 저장하고, 출처 변경 또는 만료 정책에 따라 재검증한다.

## 자동 판정

| 결과 | 조건 | 게시 |
|---|---|---|
| A 확정 | 공식 출처 1개가 장소·작품과 배우 또는 배역–배우를 명시 | 자동 |
| B 확정 | 서로 다른 도메인의 편집 출처 2개 이상이 같은 사실을 명시 | 자동 |
| 미확정 | 작품명만 있음, 커뮤니티만 있음, 한 개 편집 출처뿐임 | 배우 후보 제외 |
| 충돌 | 유효한 등장·미등장 근거가 함께 있음 | 배우 후보 제외·예외 감사 |

사람은 충돌·반복 실패·무작위 품질 표본만 확인한다. 모델 출력 자체는 신뢰 등급을 올리지 않는다.

## 영진해변 회귀 사례

원천 CSV의 `도깨비 방파제 촬영지`만으로는 김고은 등장을 확정하지 않는다. 한국관광공사
VISITKOREA 자료는 영진해변에서 `은탁(김고은)`이 김신을 만나는 장면을 명시하므로 A등급이다.
관계에는 `actor-kim-go-eun`, 자동 검증 provenance, 공식 URL을 함께 저장한다.

## 운영 원칙

- 사용자 요청 경로는 검증 DB만 조회해 비용·지연·결과 변동을 막는다.
- 누락 발견 시에만 비동기 보강하고 동일 관계·출처 결과를 캐시한다.
- 자동 판정 규칙과 대표 오탐/누락 fixture를 평가 세트로 고정한다.
- 출처 삭제·장소 이전·작품 동명이인·배우 동명이인은 재검증 또는 충돌로 보낸다.
- API 키와 원시 모델 응답은 서버/파이프라인에만 두고 클라이언트에 노출하지 않는다.
